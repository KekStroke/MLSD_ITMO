# MLSD_ITMO

**Self-Supervised Representation Learning for Rare Events in Continuous Signals**

Учебный исследовательский проект по курсу ML System Design в ИТМО: разработка
SSL-энкодера для извлечения представлений редких событий из непрерывных сигналов,
в которых преобладают фоновые данные. Экспериментальная оценка планируется на
акустических данных морских млекопитающих.

## Цель и задачи проекта

Цель — разработать и исследовать метод самосупервизорного обучения (SSL),
позволяющий извлекать информативные представления редких событий при низкой
частоте их появления.

1. Изучить существующие методы SSL для временных рядов и их ограничения при работе
   с редкими событиями.
2. Разработать подход к обучению SSL-энкодера с учётом преобладания фона.
3. Провести экспериментальную оценку на акустике морских млекопитающих.
4. Сравнить подход с существующими SSL-моделями на downstream-задачах классификации
   и обнаружения событий; исследовать применимость к другим временным рядам.

Ожидаемый результат — прототип SSL-энкодера, экспериментальное сравнение методов
и оценка качества полученных представлений. Конкретные датасеты, бейзлайны,
метрики и протокол экспериментов будут определены при заполнении дизайн-документа.

## Быстрый старт

Клонируйте репозиторий, перейдите на ветку сдачи и подготовьте окружение:

```shell
git clone https://github.com/KekStroke/MLSD_ITMO.git
cd MLSD_ITMO
git switch hw_1_setup
uv sync --locked
uv run --locked pre-commit install
uv run --locked pre-commit run --all-files
```

`uv sync --locked` создаёт `.venv` и устанавливает зависимости из lock-файла.
После установки hook проверки запускаются автоматически перед каждым коммитом.
Команды одинаковы для PowerShell, Linux и macOS; активация `.venv` не требуется.

## Проверки и автоисправление

```shell
uv run --locked ruff check .
uv run --locked ruff format --check .
uv run --locked pre-commit run --all-files --show-diff-on-failure
uv run --locked python -m compileall -q src
```

Для автоисправления используйте `uv run --locked ruff check --fix .` и
`uv run --locked ruff format .`. Pre-commit дополнительно проверяет YAML/TOML,
конфликты слияния, размер файлов, пробелы в конце строк и завершающий перевод строки.
GitHub Actions повторяет проверки при push и открытии PR.

Данные, модели, `.venv` и локальные настройки исключены из Git через `.gitignore`.
На этом этапе обучение модели и работа с датасетом ещё не реализованы.

## Порядок сдачи HW1

1. Рабочие изменения находятся в `hw_1_setup`.
2. PR с работой направляется в отдельную целевую ветку `hw_1`.
3. Ментору необходимо выдать доступ к репозиторию, а ментора и двух
   кросс-ревьюеров добавить в reviewers после получения их GitHub-логинов.
4. После ревью внести исправления; перенос работы в `main` выполняется после одобрения.

Указанные участники ревью: [germanKoch](https://github.com/germanKoch) и
[pacifikus](https://github.com/pacifikus). По требованиям курса нужны ментор и два
кросс-ревьюера; ещё один участник будет добавлен после назначения.
